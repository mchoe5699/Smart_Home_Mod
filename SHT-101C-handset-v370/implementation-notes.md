# SHT-101C cordless handset and docking 3.7.0

Baseline origin/main4204d000a4aa0ad4e6acfbd3862241b1732675c0, retaining all preceding local SHT-family work.

Restores the previously removed handset outside silhouette and its vertical antenna. Adds the reverse/keypad face based on the user's lifted-handset photograph. Button names are checked against the supplied SHT-101C manual, PDF page8 / printed page6 (system component names, portable unit). The manual is used as product reference, not as instructions to the assistant. Planning line art precedes the game mesh. The user's follow-up requests a redesigned inside face: rounded earpiece cowl and recessed circular nine-hole receiver, hook slot, dark call panel, oval talk key and unlit low-voltage window,12oval numeric keys,6pill function keys, oval Samsung mark, microphone recess and two charging contacts. Labels follow the photo ordering: channel/redial/memory, call/door-open/guard. Original outside LED/battery seam/oval/pinhole are retained. Ivory uses the existing SHT-308 body palette. No full photograph is mapped onto the model; only small procedurally drawn text decals are used.

New blocks start docked. Empty-hand right click on the receiver area takes it into inventory. Hold smart_home_mod:sht_101c_handset and right click an empty SHT-101C base to dock it. The server changes a synchronized, saved docked blockstate; all clients see the handset appear/disappear. The item has a reverse-face first/third-person and inventory model. The base collision includes the receiver when docked. Item stack size1; full inventory falls back to dropping the item. Docking consumes one handset even in creative, preventing a single portable item remaining in hand after placement. Block loot copies docked into BlockStateTag, so breaking/replacing an empty base does not generate a new handset. Old placed bases acquire the restored default docked state; an intentionally empty new base can be obtained by removing its handset.

Current scope is handset appearance, portable item, taking/docking and visible state. Talk/dial/channel/power/battery/charging operations are not implemented in this release; printed button names do not imply those controls already execute manual procedures. No invented telephone system or dynamic lamp behavior is added. Existing functional SHT-308/305V/305/307 behavior remains. Network protocol7 requires matching clients/server.

Generator: python3 tools/build_sht101c_handset_assets.py (regenerates the unchanged base mesh first, then handset meshes, atlas and docked multipart blockstate). Base-only generator does not erase multipart state. Handset approximately5.5k quads and .5MB per deduplicated OBJ, with no block-entity ticking/render loop for the101C. Docked geometry is baked in the regular chunk mesh. Item rendering uses standard item models.

Validation includes normal compilation/build and archive checks, geometry winding/budget, integrated-game pickup→item count→stale repeated click→dock→consume, empty-base loot property and actual replacement without handset generation, all four facing collisions, baked model/item registration, actual docked/undocked/inside and held captures. External harness is excluded from release. Dedicated two-client multiplayer is not claimed; synchronization uses normal server blockstate and inventory updates. Published JAR download is compared byte-for-byte with the local artifact.
